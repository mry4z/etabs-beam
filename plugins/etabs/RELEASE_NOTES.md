# v0.4.1（v2）加载确认版 · 2026-09-10

## 2026-09-10 修订

- 梁表箍筋间距统一显示中心到中心标注，例如 `2T10@200 c/c`；JSON 和计算输入仍保留原始 `@` 间距值。
- 梁表当前阶段红字门禁已收敛：锚固、搭接、抗扭周边布置列为超远期审计待办；ETABS Frame Design `Design Force` 抗震来源按项目既有确认记录不再触发当前红字。原始状态仍保留在 JSON。
- Tower 分配检查改为独立可选操作；普通梁表生成不再等待或重复执行 Tower 检查。
- 同名 Story 共享标高时，改按同标高连接关系划分 Tower Region，再在 Region 内识别异常 Tower 构件；不再仅因标高重复而切换 Tower。
- Tower 报告为 `BLOCKED` 时，界面直接显示 JSON `diagnostics` 中的原因（例如公共表字段或同标高连接拓扑不足），不再只显示“请查看报告”。
- Tower 检查日志改为阶段性字符进度条和百分比；逐对象 `records` 仅保留在 JSON/CSV 审计文件中，不再逐行刷屏拖慢界面。
- 可选 Tower 检查的 `BLOCKED` 不再被误报为插件关闭失败；只有实际梁表工作流失败、取消或未完成恢复才会向 ETABS 返回非零完成码。

本包来自 `etabs beam-v2` 当前工作区，包含分塔检查迁移提交之后的修复；不是旧目录 v0.4.0 包的重新命名。
具体提交、未提交状态和源码 SHA-256 记录在 `package-manifest.json`，完整便携运行器随包提供。
本次使用 ETABS 23 安装目录的公开 API 构建和自检；没有自动连接任何 ETABS 实际模型。

## 本版内容

- 分塔检查结束后恢复并验证完整选择集；该检查独立于普通梁表生成，可直接继续按 selected 生成梁表，且不会再次执行 Tower 检查。
- 普通运行异常、取消或关闭窗口时，等待子进程退出后恢复活动塔、单位及选择集；恢复失败明确阻断。
- 模型或选中梁改变后，旧分塔确认失效。审查 Group 仍需单独确认，不自动更改 Tower 归属、保存、解锁、分析或设计模型。
- 主梁/次梁分别输出仅含“整理梁表”的静态 Excel，无公式；原始计算和审计信息保留在 JSON。
- 保留当前 v2 次梁上筋优选及架立筋对称性调整；上部钢筋 1.2 倍放大仍由人工处理。
- 本版不包含旧目录额外的拆分、编号写回、分析/保存操作界面。

## 加载方式

1. 先由用户保存工作，移除旧插件条目，退出加载过旧 DLL 的 ETABS。
2. 将 ZIP 完整解压到新目录，保留 `workflow/`；不要只复制 DLL，也不要混入旧运行器或 ETABSv1.dll。
3. 重新启动 ETABS，在 Tools → Add/Show Plugins 中加载包根目录的 `BeamGenerator.EtabsPlugin.dll`。
4. 确认窗口显示 v0.4.1，内置引擎已就绪；config.yaml 指向新包 `workflow/BeamGenerator.Workflow/config.yaml`。
5. API DLL 选择当前 ETABS 安装目录的文件；结果目录使用新的测试目录。

分配，核对活动塔、单位、选中对象数及名称没有变化，并确认 BLOCKED 时日志/状态栏显示具体原因。再确认普通运行取消后仍保留选择集，
以及 PB/SB Excel 各只有一张“整理梁表”。
