# 梁线识别、结构分跨与 CAD 编号可执行规范

**状态**：经用户确认的业务规则；梁线/分跨、Excel/DXF 接入和模型副本写回已有可运行原型，代码实现与验收必须以本文为准。
**适用范围**：ETABS 混凝土梁几何整理、梁配筋左/中/右方向、图纸中间数据及 CAD/DXF 审核图。  
**核心原则**：先识别整条梁线（Beam Line），再根据实际支承划分结构跨（Span）。ETABS Beam Object 的分段不能直接当作结构分跨。

## 1. 概念与层级

数据必须保留以下三级关系，不能合并成一个概念：

1. **Beam Object**：ETABS 中的单个 Frame/Beam Object；可能只是由于节点、相交或建模操作形成的一小段。
2. **Beam Line**：图纸中的一条连续主梁或次梁，例如 `T2-F2-PB45`、`T2-F2-SB80`。
3. **Span**：梁线被实际支承分割后的一个结构跨，例如 `T2-F2-PB45-10`。

一个 Span 可以包含多个 Beam Object；一条 Beam Line 可以包含多个 Span。编号格式为：

```text
[楼层]-[PB或SB编号]-[跨号]
T2-F2-PB45-10
T2-F2-SB80-9
```

## 2. 最小输入数据

程序开始识别前，每个 Beam Object 至少要有：

```text
object_name, story, section, material_type,
point_i_name, point_j_name,
point_i_xyz, point_j_xyz, depth
```

另外必须取得：

- 柱 Object 的端点名称和坐标；
- 名称含 `rigid` 的柱端刚域辅助杆件及其端点；
- 固定计算单位 `N_mm_C`；完成读取后恢复 ETABS 原始当前单位；
- 坐标容差，当前默认 `1 mm`；
- 梁交点竖向容差，当前默认与坐标容差一致：平面投影相交时，必须分别沿两条三维杆件插值得到交点 Z，只有高差不超过该容差才可建立拓扑连接或支承；同楼层但不同标高不能仅凭 XY 相交而分跨；
- 源 Object 跨 Span 的有效重叠容差，当前默认 `2 mm`：支承中心线因斜交或微小建模偏差落在 Object 端点内侧不超过该值时，只把 Object 归给占据其主要长度的 Span，不因端部毫米级碎片把整个 Object 标成跨 Span；超过该值的实质重叠仍保持一对多映射并标记 `REQUIRES_SPLIT`；
- 同一跨内部折线段允许的相邻夹角，当前默认 `15°`。

非混凝土梁、无截面梁和 `rigid` 辅助杆件不作为梁线成员；`rigid` 只用于把实际柱支承位置传递到梁端。

## 3. 总体处理顺序（不得颠倒）

```text
读取 Beam Object 和柱/rigid 节点
  → 建立同楼层几何连接图
  → 识别主梁 Beam Line
  → 识别主梁的柱支承边界并分跨
  → 以已经识别的主梁作为次梁支承
  → 识别次梁 Beam Line
  → 次梁仅在主梁处分跨
  → 统一 I→J 方向和纯数字跨编号
  → 输出 JSON/CSV、Excel 和 DXF
  → 输出异常审核清单
```

必须先确定主梁，才能确定次梁的支承和跨数。不能用“所有梁交点”统一分跨。

楼层是计算隔离单元：不同楼层之间不共享梁、柱或交点，必须先按 `story` 分组。每个楼层内部独立执行上述流程；由于 ETABS 读取已在分析前完成，楼层分析可以使用 `story_workers > 1` 并行执行，最后按楼层、主次梁类型和稳定空间排序合并结果。并行与串行结果必须完全一致。

## 4. Beam Object 归入同一梁线的基本条件

两个相邻 Object 只有同时满足以下条件，才是同一 Beam Line 的候选成员：

1. 同一楼层；
2. 均为混凝土 Beam 设计方向；
3. 端点在坐标容差内相接，或两段在平面内相交且模型语义表明连续；
4. 连接后的拓扑是可排序的简单路径，不是分支或闭环；
5. 相邻段属于同一连续方向，普通折线相邻夹角不超过当前 `15°` 限值；
6. 曲率身份一致：弧形主梁不能仅因端点相接而吸收到相邻直线主梁。

**截面名称相同不是 Beam Line 身份条件。** 截面变化经常发生在柱、主梁等支承处，不能因此重新生成 `PB/SB` 编号或把跨号重置为 `1`。截面名称和尺寸必须保留在源 Object/Span 属性中；若截面在没有结构支承的跨内变化，则写入人工审核异常，但仍保持同一 Beam Line。实现上可先使用“同楼层、同截面、共点、夹角”的 `BeamMerger` 形成候选路径，再用独立的跨截面端点拓扑串接阶段恢复完整 Beam Line。

### 4.1 Step beam 与跨内多截面门禁

截面变化本身不是分跨条件。满足下列全部条件时，程序应自动把相邻不同截面的 Object 归为同一 Beam Line 和同一 Span：

1. 位于同一楼层；
2. 端点在坐标容差内相接；
3. 相邻端部切线夹角不超过项目合并角，当前为 15°；
4. 连接点不是柱、`rigid` 等效柱或该梁类型对应的其他结构支承；
5. 连通图只有一个可继续方向，不存在分叉、闭环或多个 15° 内候选。

典型回归为 `T3-F1-PB15-1` 与 `T3-F1-PB16-1`：两段只是因 step beam 截面不同而拆成 ETABS Object，若上述条件成立，应得到同一个跨、跨内两个 Object，最终名称依次为 `<SpanID>.1`、`<SpanID>.2`。

归并后一个 Span 包含两个或更多截面时，不得直接进行 I/J 或 Unique Name 写回。程序必须：

1. 标记该跨为 `REQUIRES_SECTION_REVIEW`；
2. 输出 `multi_section_span_review.json/.csv`，列明 SpanID、各截面及其 Object、路径坐标和 ETABS 审查 Group 名；
3. 可在显式变更模式下创建 `CODX_MS_<SpanID>` 原生 ETABS Group，用户可按 Group 着色，或选中 Group 高亮成员；
4. 用户确认其为同一 step beam 后，把 SpanID 写入确认清单，重新生成写回计划；
5. 用户判断不应合并时，改用人工 `MANUAL_LINE/MANUAL_SPAN` override 调整拓扑，而不是确认多截面门禁。

若相邻中心线有明显错位/间隙、连接关系不明确或截面变化同时伴随路径歧义，自动程序不得用“同高度”“近似平行”猜测归并。`GF-GRD-F-SB15-3` 与 `GF-GRD-F-SB16-1` 所示的 200×600/300×600 情况属于这一类，必须通过审查列表和 ETABS Group 由用户判断。

同一跨内即使因次梁交点、分析网格或人工操作被分成多个 Object，也要重新排序并合并为一条路径。Object 数量不影响跨数。

## 5. 主梁识别与分跨

### 5.1 主梁识别

满足以下任一情况的连续梁线判为主梁 `PB`：

1. 梁线端点或内部节点与真实柱节点连接；
2. 梁通过 `rigid` 柱端刚域与柱连接，等效为在柱支承处连接；
3. 已有人工确认的主梁覆盖表明确指定。

主梁属性应沿同一候选梁线传播，不能只把直接接触柱的那一个 Beam Object 标成主梁。

### 5.2 主梁分跨边界

主梁仅在以下位置形成 Span 边界：

- 柱中心节点或经 `rigid` 映射后的等效柱支承点；
- 梁线自由端；
- 已人工确认的其他竖向支承。

主梁与次梁相交不增加主梁跨数。柱间的多个 Beam Object 必须合并为一跨。

主梁上的内部梁交点不得替代柱支承。具体地说，若一个 PB Object 两端为柱支承，而其中部仅与其他 PB/SB 相交，则这些梁交点只是建模/拓扑节点，不切断该主梁 Span。2026-07-18 对 API ID `54204` 的复核样本中，Object `302` 的两端点 `698→696` 均为柱点；中间点 `2160` 仅连接 `T1-F1-PB22-1.1` 和 `T1-F1-SB27-1.1`，没有柱。旧算法因此把它错误分给两个结构跨；修正后 Object `302` 只贡献图纸编号 `T1-F1-PB9-3`。该场景必须作为永久回归测试。

### 5.3 主梁穿柱延续

主梁穿过柱且柱两侧路径保持同一连续直线方向时：

- `PB<n>` 保持不变；
- 柱处结束上一跨并开始下一跨；
- 跨号纯数字沿统一 I→J 方向递增。

例如：

```text
T2-F2-PB45-9  → 柱 →  T2-F2-PB45-10
```

在柱处明显转向另一条直梁或转入独立弧形梁时，不延续原 `PB<n>`，而应建立新的 Beam Line 编号。

### 5.4 连续几何线的 PB/SB 分段

同一条几何连续路径不保证全程都是主梁。应先识别柱支承核心区，再对连续路径按累计位置和主梁交点判断角色；多柱主梁、单柱连接路径和跨截面串接路径统一采用同一规则：

1. 单柱连接路径从柱端到遇到的第一个锚定主梁交点，按 `PB` 编号；
2. 越过该主梁交点后，若后续区间没有柱、只有主梁相交，则转换为 `SB`，按次梁编号和分跨规则处理；
3. 没有柱支承、仅由主梁支承的连续路径全程按 `SB` 处理；
4. 两柱或多柱主梁的柱间核心区保持 `PB`，穿过其他主梁不因此增加主梁跨数；若核心区外继续延伸，仍按最近主梁交点确定是否转为 `SB`；

名称含 `rigid` 的辅助 Frame 不进入梁表，但可作为支承传播边：只有一端已连接真实柱点的刚域链，才把支承传播到另一端；两端均未锚定的刚域不产生主梁支承。该传播在 `GeometryExtractor.column_supports()` 中完成，并同时返回三维坐标。实现必须使用 `FrameObj.GetAllFrames` 批量读取 Frame 端点、截面和坐标，再按楼层 Z 包络过滤；不得为每个 Frame 重复调用 `GetPoints/GetSection/GetCoordCartesian`。
5. PB/SB 转换点必须写入同一梁线的支承/角色边界记录，不能把源 Object 的分段直接当成跨或梁号边界。

### 5.5 PB/SB 支承角色固定点

单柱候选梁的 PB 部分会成为其他次梁的新支承，因此一次识别可能改变下一次的 PB/SB 角色。实现必须迭代到稳定拓扑：

1. 用真实柱和初始主梁候选得到第一轮 PB 路径；
2. 用当前 PB 路径重新计算所有梁的角色和次梁支承；
3. 重复直至 PB 路径集合不再变化；
4. 出现循环或 6 轮内未稳定时输出 `ROLE_REFINEMENT_NOT_CONVERGED/BLOCKED`；
5. 角色判断使用的历史交点不得自动保留为结构跨边界。相邻同角色区段只有在当前柱/等效柱或当前 PB 支承仍存在时才分跨，否则必须重新合并。

2026-07-21 实模验证中，`T1-L1-SB18` 的临时交点 `(3572.9,58563.4,5050)` 在角色细化后不再落于 PB，最终由 4 个错误 Span 收敛为 3 个有效 Span。

例如，若路径从柱 `(23072.900, 58363.400)` 延伸至主梁交点 `(15272.900, 58563.400)`，则该区间为 `PB`；从 `(15272.900, 58563.400)` 向 `(−23727.100, 58563.400)` 延伸且没有柱、只有主梁相交的区间，应改判为 `SB`。

## 6. 次梁识别与分跨

### 6.1 次梁识别

完成主梁识别后，其余由主梁支承、但不属于主梁梁线的混凝土梁判为次梁 `SB`。同一直线或允许范围内的微折线路径应跨越中间的次梁交点连续追踪。

### 6.2 次梁分跨边界

次梁只在以下位置形成 Span 边界：

- 与已识别主梁相交或连接的位置；
- 次梁自由端；
- 已人工确认的等效主支承。

最重要的不变量：

> **次梁与次梁相交，不增加跨数，不改变 `SB<n>`，也不递增跨号。**

因此，一条次梁在两条主梁之间即使被许多其他次梁分割成多个 Object，仍然只有一跨。若次梁连续穿过主梁，则主梁两侧保持同一 `SB<n>`，跨号依次递增：

```text
T2-F2-SB80-9  → 主梁 →  T2-F2-SB80-10
```

几何线段相交但 ETABS 没有共同节点时，也要计算交点；先求 XY 投影交点，再分别沿两条三维杆件插值 Z。只有交点 Z 高差不超过竖向容差，且该交点位于主梁与次梁范围内，才插入路径顶点并作为次梁分跨点。次梁—次梁的同类几何交点仍须忽略。

## 7. 弧形和折线主梁

1. 两个支承之间的弧形/折线主梁可由多个 Beam Object 组成，但整体是一条多段线路径和一个 Span。
2. 路径内部的普通折点不是分跨点。
3. 弧形主梁不能被吸收到相邻直线主梁编号中；它应建立独立的 `PB<n>`。
4. 平滑连续的同一弧形梁若经过中间柱，可保留同一 `PB<n>`，但仍须在每个柱处递增跨号。
5. 两段弧线在共同柱处若切向或曲率趋势不连续，应使用不同的 `PB<n>`；截面变化本身不构成独立编号依据，判断不唯一时写入人工审核清单，不得静默合并。

弧形梁的连续性判断至少应使用端部切向和转角趋势，不能只比较整条梁首尾弦线。

## 8. 悬挑梁

悬挑段从最后一个实际支承到自由端，单独计算一跨：

- 若它是既有 Beam Line 的连续延伸，保留原 `PB/SB` 并递增跨号；
- 若它在支承处明显转向或属于独立梁线，建立新的 `PB/SB`，跨号从 `1` 开始；
- 自由端不要求存在柱或主梁，但必须作为路径终点。

## 9. I→J 方向与编号稳定性

每条 Beam Line 只允许有一个稳定方向，所有 Span 和源 Object 均沿该方向排序：

1. 主导方向接近全局 X 时，较小 X 为 I、较大 X 为 J；
2. 主导方向接近全局 Y 时，较小 Y 为 I、较大 Y 为 J；
3. 斜梁和弧形梁以两端坐标按 X 优先、Y 次级确定稳定方向；
4. 跨号 `1、2…` 必须从 I 端向 J 端递增；
5. ETABS 梁表“左—中—右”、DXF/CAD 文字方向和 Object 局部 1 轴均使用同一有向 I→J。
6. **CAD 硬性约束**：文字方向必须保留 `local_1_direction` 的有向向量，禁止为“可读性”独立反转 180°；若文字倒置需要改善，必须通过字高、字体或版面策略解决，不能改变其 I→J 方向。方向缺失、零向量或与梁线不一致时，CAD 模块必须拒绝放置并写入审核清单。

若已有经人工确认的编号/方向映射，优先复用；否则按确定性空间排序生成 `PB/SB` 序号，并输出映射供人工审核。重新导出同一几何模型时，编号不得因 API 返回顺序变化而改变。

## 10. 可直接实现的数据结构

```python
@dataclass(frozen=True)
class BeamLine:
    beam_line_id: str          # T2-F2-PB45
    story: str
    beam_type: str             # PB | SB
    section: str
    source_objects: tuple[str, ...]
    path_points: tuple[Point3D, ...]
    is_curved: bool

@dataclass(frozen=True)
class BeamSpan:
    span_id: str               # T2-F2-PB45-10
    beam_line_id: str
    span_index: int
    source_objects: tuple[str, ...]
    path_points: tuple[Point3D, ...]
    i_point: Point3D
    j_point: Point3D
    is_cantilever: bool
```

推荐的核心接口：

```python
primary_lines = identify_primary_lines(objects, column_supports, rigid_links, settings)
primary_spans = split_primary_at_columns(primary_lines, column_supports, settings)

secondary_lines = identify_secondary_lines(objects, primary_lines, settings)
secondary_spans = split_secondary_at_primary_lines(secondary_lines, primary_lines, settings)

all_spans = orient_and_number(primary_spans + secondary_spans, settings)
validate_span_invariants(all_spans)
```

禁止使用以下错误实现：

```python
# 错误：每个合并结果都直接视为一根只有第 1 跨的梁
for merged_beam in merged_beams:
    id = next_pb_or_sb() + "-1"

# 错误：所有梁交点都增加跨数
span_boundaries = intersections_with_all_beams
```

## 11. 路径切割伪代码

```text
function split_path(path, support_points):
    在每段路径上查找落在容差内的支承点
    若支承点位于线段内部，先插入一个新路径顶点
    按 I→J 路径距离排序全部支承点
    边界 = [路径I端] + 支承点 + [路径J端]
    去重相距不超过容差的边界
    对相邻边界逐一截取多段线路径
    删除零长度跨
    返回按 I→J 排序的 Span[]
```

对主梁传入柱支承点；对次梁只传入与主梁的交点。不得把次梁交点传给次梁分跨函数。

## 12. DXF 输出规范

- 每个 Span 输出为一个独立 `POLYLINE`，路径中保留所有真实折点；
- 主梁线及编号文字：黄色；
- 次梁线及编号文字：绿色；
- 文字样式：Arial（DXF STYLE 指向 `arial.ttf`）；
- 标注内容为完整 `span_id`，插入点必须是该跨多段路径累计长度的 `50%` 位置，而不是中间顶点；
- 文字旋转方向严格跟随中点所在梁段的 I→J 局部切线；不得使用仅为可读性服务的 180° 归一化来改变有向方向；
- 文字颜色严格跟随对应梁线颜色；
- 示意图中的箭头用于解释分跨范围，正式 DXF 默认不必输出箭头；需要时放入独立审核图层；
- DXF 必须同时生成 CSV/JSON，记录编号、类型、源 Object、路径坐标、支承类型和异常状态。

## 13. 必须检查的不变量

运行结束后至少验证：

1. 每个合格混凝土 Beam Object 至少映射到一个 Span；允许真实跨支承 Object 一对多，但必须进入 `REQUIRES_SPLIT` 审计；不得丢失源 Object；
2. 每个 Span 至少包含两个不同路径点，长度大于容差；
3. 同一 Beam Line 的 Span 不重叠，并按 I→J 连续排序；
4. 主梁的内部 Span 边界都是柱/等效柱支承；
5. 次梁的内部 Span 边界都是主梁交点；
6. 次梁—次梁交点没有出现在 Span 边界集合中；
7. 弧形主梁没有继承相邻直梁的 `PB` 编号；
8. 悬挑段已单独形成 Span；
9. DXF 中多段线数量等于 Span 数量；
10. 每条多段线恰有一个同色 Arial 编号文字；
11. 同一模型重复运行得到相同编号和方向；
12. CAD 文字的有向基线与 `local_1_direction` 一致，不得出现独立反向；
13. 所有无法唯一判断的分支、环、重合梁和支承冲突均进入异常审核清单。
14. 支承边界距源 Object 端点不超过有效重叠容差时，该 Object 只能归入主要重叠 Span；不得因端部微小碎片阻塞模型编号写回。真实跨越支承且两侧有效重叠均超过容差的 Object 仍必须一对多映射。

## 14. 最小验收场景

自动化测试必须覆盖：

1. 同一直线主梁穿过三根柱：同一 `PB`，产生两个 Span；
2. 柱间主梁被多根次梁切成多个 Object：仍只有一个 Span；
3. 同一次梁连续穿过两条主梁：同一 `SB`，产生相邻 Span；
4. 同一次梁与多根次梁相交：Span 数不变；
5. 两柱之间的弧形主梁含多个 Object：独立 `PB` 且只有一个 Span；
6. 弧形主梁与相邻直梁共用柱：二者 `PB` 编号不同；
7. 柱到自由端的悬挑梁：单独一个 Span；
8. 主梁/次梁交点位于 Object 内部而非端点：插点后正确分跨；
9. 分支或闭环拓扑：不静默选择路径，写入审核异常；
10. 水平、竖向、斜向和弧形梁：I→J、跨号和文字方向稳定；
11. 相邻 Beam Object 截面变化但几何连续：保持一个 Beam Line，截面变化不新增跨；
12. 不等长折线跨：DXF 编号位于累计路径长度中点，而不是顶点数组中点。

## 15. 当前实现进度与迁移要求

当前 `BeamMerger` 的“同截面、共点、夹角限制”只适合作为 Beam Line 候选路径的一部分，不能直接决定结构跨。`src/core/beam_line_span_analyzer.py` 已增加跨截面 `_stitch_candidates` 阶段：先恢复完整 Beam Line，再按柱/主梁支承切割 Span。梁线/分跨结果已经接入 Excel、DXF 和 `src/core/model_writeback.py` 的模型副本写回原型；写回不是“尚未开发”，但在真实模型全量 CAD 复核、剩余阻塞对象审计和附属属性等价校验完成前，仍不得视为生产入口。
