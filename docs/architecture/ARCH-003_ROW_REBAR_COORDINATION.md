# ARCH-003：0.4.2 逐排纵筋与相邻跨协调算法

## 1. 输入、目标与规则权威

本架构依据用户 2026-09-10/11 指令：同一物理排纵筋同一直径，不同排允许不同直径；同跨上部第一排保持同一直径的连续基准，根数可按各区需求和箍筋支承独立，跨中允许为连续性和箍筋支承超配。适用于 PB/SB 顶、底纵筋；底筋仍按同跨需求包络通长，相邻跨底筋独立。侧面腰筋既有策略不变。

这是项目构造规则，不冒充 ACI 的“同排必须同径”条文。规范版本仍为 ACI 318-14，项目既有目录、钢筋率、保护层来源和 FrameType 解析规则继续生效。增加的连续筋面积不能免除最终配筋率、净距和横筋复核。

规范导航依据 [ACI 318-14 官方目录](https://www.concrete.org/portals/0/files/pdf/318-14-tableofcontents.pdf)：第 9 章梁、第 18.6 节 SMF 梁、第 25 章配筋构造。该公开目录仅证明章节归属，不能代替授权正文和工程签署；精确条文/例外沿用 SPEC-DET-001 的 review 状态，不宣称本次形成完整施工图 code compliance 认证。

工程解释补充参考 [NIST GCR 16-917-40，2016 第二版](https://nvlpubs.nist.gov/nistpubs/gcr/2016/NIST.GCR.16-917-40.pdf)，该指南明确以 ACI 318-14 为依据。其第 5 章说明实配梁筋影响梁端可能抗弯承载力及相关容量设计，因此连续性超配必须进入最终实配复核，不能仅增加显示面积。项目的剪力来源和当前审查阶段仍按 ADR-0008 执行。

## 2. 逐排数据合同

引入不可变物理排对象，每排至少包含 `count`、`diameter_mm`、`role`、`credited_area_mm2`；排列从相应混凝土受拉面向截面内侧编号。LongitudinalDesign 持有有序 rows，并由 rows 唯一派生总面积、层数、最小/最大主筋直径和 notation。

- 每排一种直径、至少两根；不能将两个直径的 BarSpec 子组拼成同一排，也不能生成单根附加排。
- `4T25/2T20` 精确表示第一排 4 根 T25、第二排 2 根 T20；同径分排也明确输出 `4T25/3T25`，禁止把总根数当第一排。
- 第一排是连续且有明确强度计入规则的主筋；新生成结果不得用同排小直径括号架立筋补足肢数。若有不计强度的构造筋，仍须满足物理排同径，计入面积标识不得从括号字符串推断。
- 可保留 BarSpec 等兼容视图，但必须由 rows 单向派生；禁止 rows 与 bars 各自修改。所有使用 `bars[0]`/`bar.layers` 的计算消费者须改为完整排信息。
- 旧 payload 2.0/2.1 仍可读取；新增逐排字段采用 additive schema 2.2，重新计算后才写入新 policy/version。旧混排结果只按旧版本展示或从 raw_rows 重算，不能仅改字符串就标成新规则合格。
- JSON 对各跨 L/M/R 顶底保存真实 rows、required/provided、第一排约束来源、公共支座关系、候选拒绝理由及最终状态；Excel 仅投影计算结果。

## 3. 跨内选筋

1. 保留既有材料、FrameType、Total/Face 及箍筋初选链。有限钢筋目录中枚举第一排直径和根数，受每排净距/截面高度限制；同跨上部第一排 L/M/R 直径一致，根数可按各区需求独立选择，但每区必须满足本区箍筋支承。
2. 先计算贯通第一排提供面积，再按各区实际需求添加第二排及允许的后续排。不同附加排可选不同直径；不要求第二排直径大于第一排。当前项目所有纵筋均按 Total 面积求解并受允许排数上限约束；旧 Face 模式不再是候选路径，face/腰筋仅作为独立构造输出。
3. 所有区段都可选择仅第一排；跨中不因 As 较小而减小第一排直径、改为两根小筋或加入同排异径架立筋。跨中需求较大时允许增附加排，不能把该区需求压回第一排面积。
4. 候选必须先满足每排容量、排间对齐/净距、总高度、各区所需面积、适用的最小/最大筋率及箍筋支承。不得沿用单排 db/2 简化去冒充多排重心：显式净保护层模式按真实排重心计算有效高度；ETABS 重心 cover 模式保留其语义，解出排布位置并验证实际保护层可行性，矛盾时明确失败。
5. 底筋在同跨 L/M/R 包络下选择一套逐排方案，三段统一；不向相邻跨传播。旧 `_mixed_candidate`、`_lap_overlap_design`、minimum-credit/hanger 的同排异径途径不得继续进入新结果。

用户例：当截面容量允许第一排四根、已选四肢箍，且左端需求由 `4T25/2T20` 满足、右端由 `4T25/3T25` 满足时，跨中需求约 1100 mm² 可采用 `4T25`（面积约 1963.5 mm²）。记录超配由连续筋及箍筋支承控制。该例是候选/构造验收样例，不强迫所有梁一律选四根 T25。

## 4. 跨间：共同可行域与确定性求解

原局部先选最优、再跨间改写、再跨内重算的双向覆盖不再作为最终求解方式。构建梁线连续片段（同 beam_line、相邻 span_no、有效输入），从每跨可行候选中选择全片段兼容组合。

- 已解析 NON_SWAY/OMF/IMF/SMF 之间的不同不是自动失败条件。公共支座候选须在两侧各自截面、保护层、箍筋、材料和 profile 下分别通过；保留两侧 profile，绝不统一改成较弱或较强类型以绕过检查。UNKNOWN、缺失和单跨混合未确认输入仍保持原门禁。
- 精确连续模式：同一跨 L/M/R 的第一排直径相同，根数可按各区需求和箍筋支承独立。公共支座按物理排对齐：对应排层数及直径一致，但第一排根数不强制相同；两侧各自仍须满足本侧箍筋肢数、净距、面积和几何校核。PB Option 2 允许在需求大侧增加根数或新增完整附加排，至少两根、对齐要求仍有效。
- 先枚举可行贯通基排状态，再组合各跨 L/M/R 附加排候选。用沿梁线动态规划/等价有限候选约束求解筛除不兼容支座；状态保留实际支座 rows 签名和各跨最终几何约束，不只保存一个直径或 notation 字符串。不能因局部最优不可协调便宣布无解；必须尝试其他可行候选。
- 候选排序按硬约束后依次：少排数、少规格变化、保持既有 PB 箍筋肢数优选和 SB <=T20 软偏好、少超配面积、少根数、数值行签名确定性打破平局。跨中超配不得在排序中反向打破贯通基排硬约束。
- 箍筋与纵筋反馈仍须闭环：对选定实际 rows 重新计算有效高度、最小/最大面积、最终 db、剪扭与现有容量剪力流程、构造几何审计。失败时淘汰该组合或更新箍筋候选并重新求解；记录完整状态集合，重复状态不得标 STABLE。几何可行域有限，不用简单增加旧迭代次数来掩盖循环。
- 缺失跨、非法输入形成边界，不跨缺号或未成功设计跨建立连续关系。某连续片段无解仅使其相关片段保留候选/失败；不得把同名梁线其他不连通片段清空。输出具体失败支座、两侧类型/截面及拒绝原因，区分无可行布局、资料不足和迭代未收敛。
- 完成后重新生成所有面积、rows、几何审计、SMF/剪力状态和原始需求对照；不得仅替换 Excel 文本或沿用变更前审计。

## 5. 实现边界与验收

核心 rows/候选/协调保持纯 Python；`src/rebar_workbook.py` 负责分组、raw_rows 重放及结构化输出；Python/Node 静态表仅按统一 notation/rows 显示。配筋策略版本与插件 0.4.2 同时更新，避免旧 0.4.1 运行器被误包装成新算法。

必须通过：同排异径拒绝、异排可异径、禁止单根末排、四肢示例、跨中需求反控、窄截面无解、排间净距/高度/重心、混 profile 支座两侧独立复核、Option1/2、SB、底筋独立、多跨次序无关/幂等、真实无解与缺号片段隔离、旧 payload 重算、JSON/两种 renderer 一致、最终箍筋/db/钢筋率反馈。真实样本按 raw_rows 离线重算，不操作 ETABS，不覆盖输入目录；逐行报告状态迁移，不承诺把所有行强制变为 OK。
