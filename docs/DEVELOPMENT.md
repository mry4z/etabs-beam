# ETABS Beam Generator 开发指南

## 本地环境

```powershell
python -m pip install -r requirements.txt
python -m pytest tests/unit -q
```

ETABS 集成测试不会默认运行。打开目标模型后，以与 ETABS 相同权限级别执行：

```powershell
$env:ETABS_INTEGRATION='1'
python -m pytest tests/integration -q
```

## 代码边界

- `core/`：仅负责 ETABS 连接、几何提取和连续性分析；
- `design/`：将 ETABS 原始设计数组映射为稳定数据模型；
- `excel_export.py`：只消费数据模型，不直接访问 ETABS；
- `workflow.py`：编排流程，不堆积业务算法；
- `utils/`：可复用的日志、文件路径和纯计算工具。

## 单位约束

当前 MVP 固定在 `N_mm_C` 下导出。工作流使用 `temporary_present_units()` 在 `try/finally` 中恢复 ETABS 原单位。任何新增 OAPI 读取方法都必须在这一上下文内执行，或明确说明其单位来源。

## 验证要求

新增代码至少应包含以下一项：

- 不依赖 ETABS 的单元测试；
- 需 ETABS 的 opt-in 集成测试；
- 对 `docs/ETABS_OAPI_VALIDATION.md` 的调用签名和实测记录更新。

提交前运行：

```powershell
python -m pytest tests -q
python -m compileall -q src
python -m black --check src tests
python -m flake8 src tests
```

当前离线覆盖率门槛为 60%（首个可执行基线）；后续应在补足 ETABS 适配层的 mock 测试后逐步提高。

## 设计原则

### 1. 显式处理拓扑异常，按定义策略降级

**原则**：对图搜索、路径遍历等拓扑操作，**必须显式检测和处理非预期的拓扑结构**（分支、环、孤立节点），不能静默丢弃数据；允许降级，但降级策略必须明确、可追踪。

**原因**：连续性分析、梁段合并等算法常假设简单路径拓扑。真实模型中若出现分支节点（例如 3+ 根梁交于同一点），遍历会提前终止或陷入无限循环，导致某些梁被丢弃，后续导出时 `KeyError` 崩溃。用户难以察觉根因。

**应用**：
- 在图遍历（DFS/BFS）开始前，补充度数检测；如果出现度数 ≥3 的节点，显式记录警告或报错。
- 对梁段合并，`_is_simple_path()` 检测必须同时验证"恰好 2 个度数为 1 的端点"且"所有其他点度数 ≤2"。
- 补充单元测试覆盖分支拓扑、环拓扑、孤立节点等边界案例；测试用例应包括真实模型特征（例如梁在柱顶多重相交）。

### 2. 配置项与实现必须一致

**原则**：配置文件中声明的项目必须在代码中被使用；若不使用，删除配置项而不是放任它成为"死配置"。若代码行为需要可配置，则该项必须被正确读取和应用。

**原因**：用户根据配置文档调整参数时，假设该参数会影响行为。死配置导致用户困惑且难以调试。

**应用**：
- 在合并代码时，检查每个新配置项的引入是否有对应的 `config.<field>` 访问代码。
- 若某个配置项在多次审查中被发现未使用，立即删除或制定修复计划并在 TODO 中明确标记。
- 配置参数的默认值、范围和敏感性应在 `config.example.yaml` 注释中说明。

### 3. 区分数据模型的设计语义

**原则**：`BeamDesignResult` 与 `DesignStation` 中的字段应明确标示其工程语义（弯矩驱动 vs. 扭转驱动、纵筋 vs. 横筋），避免名称与 ETABS OAPI 字段名之间的语义漂移。

**原因**：梁配筋设计涉及多种受力形态（弯矩、扭转、剪力），ETABS 返回的 `TopArea` / `BotArea` / `TLArea` / `TTArea` 等字段名称对工程师不够直观。若代码映射不清楚，导出的梁表容易被误读。

**应用**：
- 字段命名采用 `<direction>_<type>_<driven_by>` 模式，例如 `top_flexural_area`（顶部纵筋，由弯矩驱动）、`torsion_trans_area`（扭转横筋）。
- 在数据模型和梁表列头中同时添加工程注记，例如"顶部弯矩纵筋（不含受扭钢筋）"。
- 当新增字段时，务必同时更新单元测试和梁表列定义，确保语义从代码到输出一致。

### 4. 设计结果的粒度观测与报告

**原则**：对 ETABS 返回的设计结果，**不仅检测是否为 `None`，还要检测是否为空数组**；对不同类别的缺失进行分类报告，帮助用户诊断模型问题。

**原因**：当混凝土梁通过导入筛选但设计站点数组为空时（例如模型未完成设计分析），若与非混凝土截面跳过混为一谈，用户将看不到缺设计结果的警告。

**应用**：
- 在 `workflow.py` 中分别统计"非混凝土截面跳过"和"混凝土梁但缺设计结果"两个类别。
- 后者应作为单独的警告记录在异常记录表或日志中。
- 在梁表或设计站点表中对缺结果的梁进行标记（例如空值单元格加备注）。

### 5. 参数敏感性需要验证

**原则**：对影响主要输出的数值参数（如几何容差、归并夹角、端点区深度倍数），**参数改动后必须用真实模型重新验证，确认影响范围**。不应凭推理直接改大参数范围。

**原因**：归并夹角从 3° 扩大到 15° 是一次数量级的改动（从"毫厘折线梁"到"真实转角梁"），可能导致工程上不该合并的两根梁被误判为一根逻辑梁。改动前后的梁合并数量、设计站点数应被追踪和文档化。

**应用**：
- 对参数改动，在 `docs/ETABS_OAPI_VALIDATION.md` 的实测记录中分别记录改动前后的数字（例如"3°时 803 条合并"vs."15°时 XXX 条合并"）。
- 若参数改动导致输出显著变化，应补充工程评估（例如"15°合并结果中是否存在无效合并导致截面超配"）。
- 参数改动应作为 TODO 项进入 `PROJECT_COMPLETION_CHECKLIST.md` 的重要-紧急矩阵，并在下一次真实模型验收时才能销项。
