# 逻辑梁编号、局部坐标与图纸中间数据规范

> 梁线、主次梁支承关系、分跨、弧形梁和悬挑梁的可执行判据，统一以 [BEAM_LINE_SPAN_RULES.md](BEAM_LINE_SPAN_RULES.md) 为准；本文负责编号方向和图纸中间数据接口。
>
> 当前状态（2026-07-18）：ETABS 模型副本的 I/J 整理和 Unique Name 两阶段写回已有全量可运行原型；JSON/CAD 插件仍是后续交付项。

## 目标

让 ETABS 模型、梁配筋表和 CAD 图纸共用同一套有向梁方向：**逻辑梁 I 端 → J 端 = 局部 1 轴正向 = 梁表左 → 中 → 右 = 图纸编号文字方向**。

这是配筋位置的硬约束，不是显示偏好：CAD 模块不得为了避免文字倒置而把文字独立旋转 180°。文字方向一旦与 I→J 不一致，梁表左/中/右钢筋位置将与图纸错位，必须拒绝输出并记录审核错误。

该功能分为“模型整理”和“图纸数据”两层。两层必须使用同一条逻辑梁方向，但 ETABS 模型修改必须先预览、确认和备份，不能随导出自动执行。

## 1. 编号规则

图纸逻辑梁编号采用：

```text
[楼层]-[主次梁]-[跨编号]
F1-PB5-3
RF-SB10-1
```

- `PB`：主梁；`SB`：次梁；主次梁判定以柱/刚域节点和逻辑梁拓扑为基础，必须允许人工复核。
- 最后一字段为纯数字跨编号，例如 `3`；不得添加 `S` 前缀。
- 一个逻辑跨若由多个 ETABS Beam Object 组成，图纸仍只使用一个逻辑梁编号。
- 若后续需要重命名 ETABS Object Unique Name，则使用 `F1-PB5-3.1`、`F1-PB5-3.2` 等段号；段号只区分模型对象，不改变图纸逻辑梁编号。
- 编号格式必须由一个共享的 `NumberingPolicy/SpanIdResolver` 生成，ETABS 写回、Excel、DXF、CSV 和 JSON 不得各自拼接或各自在导出时删除 `S`。内部算法若仍保留旧式 `-S3` 标识，只能作为迁移期内部键，任何交付字段都必须输出 `-3`。

## 2. ETABS 局部坐标整理（必须保留）

逻辑梁编号并不替代模型局部坐标整理。对每一根逻辑梁，先确定一条稳定的 I→J 方向，再将其组成的全部 Beam Object 整理为同向：

1. 近水平梁以较小 X 为 I、近竖向梁以较小 Y 为 I；斜梁按项目图纸正方向向量或确定性的 X 优先/Y 次级排序。这里的“负向→正向”表示坐标递增方向，不表示 I 点坐标必须为负数。
2. 多段折线梁沿逻辑路径连续排序，每段的局部 1 轴均指向逻辑 J 端；文字必须继承该有向路径，不能单独反向。
3. 名称含 `rigid` 的柱端刚域辅助杆件视为柱连接辅助对象：不进入混凝土梁表、不计入主次梁跨编号、不作为梁对象重定向目标。
4. 完成后重新提取模型，验证所有段的 I→J 顺序、逻辑编号、梁表左/中/右位置和 CAD 文字方向一致。

模型重定向属于显式模型修改操作。实施时必须创建可恢复备份，检查荷载、释放、局部轴、连接关系和设计结果有效性；必要时重新分析和设计。当前实现已经在 ETABS 22/23 工作副本上验证 `EditFrame.ChangeConnectivity(Name, old_j, old_i)` 反向、`FrameObj.ChangeName()` 两阶段改名、GUID 保持、全属性比较、回滚和保存重开幂等性。剩余 `REQUIRES_SPLIT`、多截面和需求复核对象继续 fail-closed。

## 3. 图纸中间数据文件

先导出一份与 CAD 软件解耦的 JSON（可同时提供 CSV 摘要）。每条逻辑梁至少包含：

```json
{
  "logical_beam_id": "RF-SB10-1",
  "story": "RF",
  "beam_type": "SB",
  "span_index": 1,
  "source_objects": ["RF-SB10-1.1", "RF-SB10-1.2"],
  "i_point": [0.0, 0.0, 0.0],
  "j_point": [6000.0, 0.0, 0.0],
  "path_points": [[0.0, 0.0, 0.0], [3000.0, 0.0, 0.0], [6000.0, 0.0, 0.0]],
  "midpoint": [3000.0, 0.0, 0.0],
  "local_1_direction": [1.0, 0.0, 0.0],
  "vertical_intersection_validated": true,
  "numbering_policy_version": "...",
  "topology_version": "..."
}
```

坐标使用模型平面坐标并带明示单位、模型路径和导出时间。编号、源对象、方向和路径必须可追溯。中间数据还必须记录原模型/工作副本哈希、ETABS 版本、算法版本、支承来源（真实柱、`rigid` 等效柱或 PB）和异常状态；Z 高程未通过或 `rigid` 支承传播未完成的记录不得标记为可出图。

## 4. CAD 插件职责

1. 读取中间数据并按 `logical_beam_id` 写入图纸；不从 CAD 线条猜测编号。
2. 文字按逻辑梁中点布置，文字方向必须与 `local_1_direction` 的有向向量一致；禁止使用“文字可读性”规则把方向翻转 180°。
3. 文字插入点采用“中下”；其插入点投影到梁中线上方一侧的梁边线中点。
4. 一根梁有两条边线时，“上方”由文字朝向的法向确定；插件仅在指定梁线图层中寻找该侧边线。
5. 若文字与梁线存在偏移，沿法向投影/移动到目标边线中点；碰撞、跨中无梁线、图层缺失或方向不明时写入 CAD 审核清单，不静默放置。

## 验收顺序

1. 小模型验证逻辑梁编号、Object 段号和局部 1 轴方向。
2. 验证 ETABS 梁表左/中/右与 I→J 一致。
3. 验证 JSON/CSV 坐标和编号。
4. CAD 插件在一根直梁、一根折线梁、两边线梁和文字碰撞场景中验收；另须覆盖 I→J 与屏幕常规阅读方向相反的梁，确认文字仍保持 I→J 有向方向且左/中/右配筋不交换。
5. 方向字段缺失、零向量、与梁线切线不一致或插件尝试独立反向时，必须阻止出图并写入错误清单。

## 当前成果有效性与后续事项

- Object `302` 的复核证明，PB 内部只有梁交点、没有柱时不得增加主梁跨数；其正确图纸编号为 `T1-F1-PB9-3`，不能拆成两个跨。该规则和完整拓扑状态以 `BEAM_LINE_SPAN_RULES.md` 为准。
- 旧算法生成的 v6.4.1 3,070 跨 DXF/Excel/写回副本，以及 v6.4.3 3,074 跨 Excel，已经因 PB 内部交点修正而失效，只保留为历史证据。正式 CAD/Excel 必须基于当前 3,010 跨结果重建。
- 当前仍有 24 个源 Object 因实质跨越多个 Span 标记为 `REQUIRES_SPLIT`；它们必须在中间数据和诊断 DXF 中显式列出，不能选取任一 Span 名称强制写回。
- 进入 CAD 插件开发前必须先完成 `rigid` 等效柱支承传递和梁交点 Z 高程校验；两者均属于拓扑输入契约，而不是 CAD 端补救逻辑。
- CAD 验收增加机器校核：文字基线单位向量与 `local_1_direction` 点积应接近 `+1`；点积为负表示发生 180° 翻转，必须阻止出图。
