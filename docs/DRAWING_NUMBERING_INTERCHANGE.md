# 逻辑梁编号、局部坐标与图纸中间数据规范（远期）

> 梁线、主次梁支承关系、分跨、弧形梁和悬挑梁的可执行判据，统一以 [BEAM_LINE_SPAN_RULES.md](BEAM_LINE_SPAN_RULES.md) 为准；本文负责编号方向和图纸中间数据接口。

## 目标

让 ETABS 模型、梁配筋表和 CAD 图纸共用同一套梁方向：**逻辑梁 I 端 → J 端 = 局部 1 轴正向 = 梁表左 → 中 → 右 = 图纸编号文字阅读方向**。

该功能分为“模型整理”和“图纸数据”两层。两层必须使用同一条逻辑梁方向，但 ETABS 模型修改必须先预览、确认和备份，不能随导出自动执行。

## 1. 编号规则

图纸逻辑梁编号采用：

```text
[楼层]-[主次梁]-[跨编号]
F1-PB5-3
RF-SB10-1
```

- `PB`：主梁；`SB`：次梁；主次梁判定以柱/刚域节点和逻辑梁拓扑为基础，必须允许人工复核。
- 最后一字段为纯数字跨编号，例如 `3`；不得添加 `S` 前缀。
- 一个逻辑跨若由多个 ETABS Beam Object 组成，图纸仍只使用一个逻辑梁编号。
- 若后续需要重命名 ETABS Object Unique Name，则使用 `F1-PB5-3.1`、`F1-PB5-3.2` 等段号；段号只区分模型对象，不改变图纸逻辑梁编号。

## 2. ETABS 局部坐标整理（必须保留）

逻辑梁编号并不替代模型局部坐标整理。对每一根逻辑梁，先确定一条稳定的 I→J 方向，再将其组成的全部 Beam Object 整理为同向：

1. 优先使 I 端处于全局 X/Y 的负向、J 端处于正向；斜梁按 X 优先、Y 次级的稳定判据确定。
2. 多段折线梁沿逻辑路径连续排序，每段的局部 1 轴均指向逻辑 J 端。
3. 名称含 `rigid` 的柱端刚域辅助杆件视为柱连接辅助对象：不进入混凝土梁表、不计入主次梁跨编号、不作为梁对象重定向目标。
4. 完成后重新提取模型，验证所有段的 I→J 顺序、逻辑编号、梁表左/中/右位置和 CAD 文字方向一致。

模型重定向属于显式模型修改操作。实施时必须创建可恢复备份，检查荷载、释放、局部轴、连接关系和设计结果有效性；必要时重新分析和设计。ETABS API 的具体“端点反向”方法须在独立试验模型验证后才可用于生产模型。

## 3. 图纸中间数据文件

先导出一份与 CAD 软件解耦的 JSON（可同时提供 CSV 摘要）。每条逻辑梁至少包含：

```json
{
  "logical_beam_id": "RF-SB10-1",
  "story": "RF",
  "beam_type": "SB",
  "span_index": 1,
  "source_objects": ["RF-SB10-1.1", "RF-SB10-1.2"],
  "i_point": [0.0, 0.0, 0.0],
  "j_point": [6000.0, 0.0, 0.0],
  "path_points": [[0.0, 0.0, 0.0], [3000.0, 0.0, 0.0], [6000.0, 0.0, 0.0]],
  "midpoint": [3000.0, 0.0, 0.0],
  "local_1_direction": [1.0, 0.0, 0.0]
}
```

坐标使用模型平面坐标并带明示单位、模型路径和导出时间。编号、源对象、方向和路径必须可追溯。

## 4. CAD 插件职责

1. 读取中间数据并按 `logical_beam_id` 写入图纸；不从 CAD 线条猜测编号。
2. 文字按逻辑梁中点布置，文字方向与 `local_1_direction` 一致。
3. 文字插入点采用“中下”；其插入点投影到梁中线上方一侧的梁边线中点。
4. 一根梁有两条边线时，“上方”由文字朝向的法向确定；插件仅在指定梁线图层中寻找该侧边线。
5. 若文字与梁线存在偏移，沿法向投影/移动到目标边线中点；碰撞、跨中无梁线、图层缺失或方向不明时写入 CAD 审核清单，不静默放置。

## 验收顺序

1. 小模型验证逻辑梁编号、Object 段号和局部 1 轴方向。
2. 验证 ETABS 梁表左/中/右与 I→J 一致。
3. 验证 JSON/CSV 坐标和编号。
4. CAD 插件在一根直梁、一根折线梁、两边线梁和文字碰撞场景中验收。
